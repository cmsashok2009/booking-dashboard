# Booking Dashboard Agent Rules

1. Read `plan.md` before changing this repository.
2. Use UX and UI skills for every user-facing change.
3. Use API skill for every backend, persistence, integration, security, or contract change.
4. Use all three skills for end-to-end features.
5. List applicable IDs before implementation and report them after verification.
6. Store evidence in `docs/quality-reports/<feature>.md` using the report template.
7. Do not declare completion with unresolved Critical/High failures, unjustified N/A, missing tests, or missing browser evidence.
8. Update `plan.md` status and Verification Notes after each phase.

Never expose passwords, activation tokens, provider secrets, or personal data in logs, screenshots, toasts, or persistent browser storage.
